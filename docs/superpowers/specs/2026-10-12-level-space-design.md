# Track：紧凑 Level 主界面与等级配色设计

日期：2026-10-12

状态：用户已确认 A 的 Strength Rank 方向、单屏布局、仅左上使用 Rank、其余使用数字等级，以及“Level 配色 / Home 绿色 / 有氧灰白”的范围。本书面设计等待用户审阅；本次提交仅保存设计，不修改产品代码。下文明确标出的配色分段和详情承接方式，是这份设计提出的具体规则，尚不能视为用户已经确认。

## 1. 目标与范围

让用户打开 Level 就能看清整体力量段位、经验等级和七类训练等级，同时让成长有可辨认的视觉变化。专业表达与成就感平衡，不把经验、力量和训练部位混为一谈。

主界面在常规竖屏和默认字号下无需滑动；不靠缩小整个界面、隐藏入口或牺牲可读性达成这一点。详细信息通过主动点击进入，不堆在主界面。

本轮只实现显示、导航和等级配色。不新增真实力量评估、XP 结算、等级增长、账号服务、付费功能、排行榜或发布流程。现有动作姿势问题不在本轮修正，也不重新生成人体解剖插画。

## 2. 已确认的主界面结构

从上到下：页面标题；两张左右并排且同等重要的摘要卡；七个训练区域；现有底部导航。

```text
Level
┌─────────────────┬─────────────────┐
│ Strength Rank   │ Experience Level│
│ 段位徽章 + 名称 │ 大号 Lv. 数字   │
│                 │ XP + Review     │
├─────────────────┼─────────────────┤
│ Chest · Lv.     │ Back · Lv.      │
├─────────────────┼─────────────────┤
│ Shoulders · Lv. │ Legs · Lv.      │
├─────────────────┼─────────────────┤
│ Arms · Lv.      │ Core · Lv.      │
├─────────────────┴─────────────────┤
│ Cardio · Lv.，灰白跑步人物         │
└───────────────────────────────────┘
现有底部导航
```

- 左上仅用 Strength Rank，显示有辨识度的徽章和段位名称，不同时再放整体 `Lv.26`。
- 右上为 Experience Level。数字的视觉分量与左边徽章相当，不再成为小字附属信息。
- `Review Progress` 放在 Experience 卡片内，是明确可点击的按钮，不另占一整排。
- 下方六张人体卡两列三排；Cardio 独占最后一排。卡片展示真实 HTML 部位名称、数字 `Lv.`、已有插画，不展示部位 Rank 名称。
- 顺序复用 Home 的稳定 ID：`chest → back → shoulders → legs → arms → abs → cardio`。`abs` 的英文显示名仍为 Core，不改 ID。
- 主界面移除雷达图、独立称号横条和其他扩展模块。既有称号功能仍可从详情进入，不删除其实现。
- 沿用现有深色底、圆角和线条语言；不增加商城、头像换装、持续闪烁或大型装饰动画。

以前浏览器中的紧凑 A 草稿只用于验证布局；其中部位段位名称和绿色高亮已被上述最新要求取代，不能作为最终实现已完成的证明。

## 3. 数字等级与颜色：本设计提案

颜色按数字等级分段变化，不是每升一级就换一种颜色。每张卡始终显示准确数字，同一分段内等级不同但颜色相同属于预期行为。

| 数字等级 | 肌肉高亮颜色 | 主色标记 |
| --- | --- | --- |
| Lv.1–9 | 绿色 | `#32D992` |
| Lv.10–19 | 蓝色 | `#62B5F6` |
| Lv.20–29 | 紫色 | `#B49AF6` |
| Lv.30–39 | 金色 | `#EBC76F` |
| Lv.40 及以上 | 冰银色 | `#BDECF1` |
| 未评估或无有效等级 | 中性灰 | `#8B9CA5` |

以上是视觉分段，不是经验证的力量标准，也不代表医学意义、身体素质百分位或其他软件的评分。有限的正整数是有效等级；缺失、零、负数、小数、字符串或非有限数不生成虚假 `Lv.0`，显示“未评估 / Not assessed”。

现有样例中，六个力量部位均为 Lv.20–27，因此默认都落在紫色分段。不要为了显得颜色丰富而修改用户数据或伪造等级差异。验收用独立测试数据覆盖低、中、高等级和未评估状态，不在主界面加入演示等级切换器。

### 配色范围和保真要求

- 仅主 Level 页六张身体部位卡启用等级配色。Home 继续用原绿色表示训练部位，现有训练与详情配图不作全局换色。
- 只替换现有绿色肌肉区域及其绿色边缘、阴影；银白人体轮廓、非目标肌肉、姿势、比例和深色背景保持原样。
- 不对整张图片使用色相旋转、着色覆盖或全图饱和度变化。
- 在未评估状态中，仅将原高亮区域转为中性灰，保留完整轮廓；不把“未评估”解释成低水平。
- Cardio 的所有等级始终使用同一灰白跑步插画，无肌肉高亮。数字仍按正常等级规则显示。
- 不在图片里写部位名称、等级或段位文字；这些信息由 HTML 和语言词典提供。
- 原图及已批准的去字副本均保持字节不变。原图来源与提示词记录继续保留。

实现采用独立的 Level 插画显示边界，复用现有裁切位置。换色方法必须先证明能隔离原绿色区域，再接入六张卡；不通过重新描绘人体来掩盖分割不准确的问题。具体显示技术在实施计划中确定，不引入新的前端框架。若无法保持轮廓与背景，需要先报告限制，不以全图滤镜代替此要求。

## 4. Strength 与 Experience 的含义

Strength Rank 表达力量表现；Experience Level 表达训练积累。XP 不直接增加 Strength Rank；颜色取决于部位数字等级，而不是 XP 或整体 Rank。

仓库目前没有真实力量评分或 XP 成长算法。部位等级、整体等级和经验进度是固定原型数据，保存训练只记录历史和更新已有训练完成状态。本轮不偷偷加入一套未经确认的估算公式。

初始展示保留现有数字等级；整体 Rank 使用 A 草稿的示例 `Gold II`；Experience 保留 `Lv.27`、`12,450 / 18,000 XP`。进度条从同一对 XP 数值计算，避免文字与条长相互矛盾。原型提示中明确这些是示例数据，详情解释其非评估结果。

徽章使用一致的图形系统。测试覆盖低阶简洁、中阶金色分层、高阶冰银精致三种表现，重点是结构与辨识度，不只改变一行名称。它们是可替换的展示样例，不据此宣称已经建立完整段位晋升标准。无整体评估时使用中性徽章和“未评估”，不显示伪造的 Gold。

不在主界面加入虚构的“距升段还差多少 kg”、训练次数奖励、过去趋势或自动晋升提示。真实成长规则、评估所需数据和安全训练建议应作为后续独立设计。

## 5. 详情与返回：本设计提案

`Review Progress` 进入一个只读的 Progress 详情页，底部导航继续标记 Level，返回按钮回到 Level。现有 Profile → Stats 不被改名或替换；既有页面继续可用。

Progress 内容限于当前 Experience 数字等级、同一组示例 XP、距下一经验等级的 XP 差额、Strength 与 XP 的分离说明，以及既有称号入口。明确标注样例来源，不新增假训练趋势、假提升百分比或未实现的分享按钮。称号页继续按既有路径返回 Level。

六个力量部位卡进入现有 Muscle 详情，保留数字等级、动作列表、历史和 PR。切换部位时遵守原有部位筛选规则，避免将胸部动作筛选用于背部。

Cardio 进入现有有氧动作列表，而不是包含 kg 和力量组数的 Muscle 历史。由 Level 打开的列表提供回到 Level 的返回入口；由 Home 打开的列表仍返回 Home。选择动作和记录有氧继续复用现有训练流程。

仅浏览主 Level、Progress 或切换语言，不结算训练、不写入历史、不清空尚未保存的重量、次数、有氧距离或历史筛选。语言切换保持当前页面和输入；主动切换部位时执行上一段的部位筛选规则，主动选择其他动作时沿用原有动作切换行为。

## 6. 实现边界

- 小型展示模块集中管理数字等级到配色的映射、有效值判断和示例摘要。颜色不是业务评分，也不写回训练数据。
- 主 Level 使用 Home 的七部位目录，不复用雷达的旧排列去改变其他消费者。
- Level 专用插画渲染接受稳定部位 ID 和颜色标记；默认 Home 插画渲染继续保持绿色。不存在第二套语言业务代码。
- 进度详情增加一个明确页面入口，复用现有导航、页面渲染和国际化模式；不引入路由库或新的运行依赖。
- 展示模块的缺失数据回退为“未评估”；图片加载失败时保留真实文字和等级，不能使卡片失去可点击名称。
- 不改 `track.training-history.v1` 的存储结构、日期或 numeric kg/km 值，不进行数据迁移。
- Free 和 Track Pro 都使用同一 Level 展示，不把数字等级或配色作为新增付费门槛。
- 英文仍是公开基线。新增文案同时编辑 `mobile/locales/en.json` 和 `zh-CN.json`，生成 `messages.js`；中文仍只能通过明确的内部预览配置开放。
- Profile 等其他页面的现有数字等级展示保持不变；本轮不扩大到所有页面的整体重设计。

## 7. 布局、触控与可访问性

默认字号下验收 320×740、390×844、430×932 三种竖屏视口，覆盖英文及中文内部预览、Free 与 Pro。标题、两张摘要卡、七个入口和底部导航完整可见；无主内容纵向滚动、横向溢出或导航遮挡。

优先收紧装饰空间和图片尺寸，保留可读文字。摘要卡等高，Experience 大号数字与 Strength 徽章具有同等关注度。长段位名称允许有控制的换行；不截断到无法识别，也不使用全页缩放满足验收。

所有入口使用真实按钮，触控范围至少 44×44 CSS 像素。数字等级和读屏名称始终存在，不依赖颜色传达等级；键盘焦点清楚。图片仅为辅助，避免重复读屏。

系统大字号、浏览器放大、横屏或更小的可用高度下，允许安全滚动兜底，不锁定缩放、不裁掉内容。“无需滑动”不意味着在这些可访问性场景下禁用滚动。已有原型预览开关若占用额外空间，应计入实际可用高度。

不新增持续动画或新的动画依赖。既有按压反馈遵守减少动态效果偏好。浏览器验收不能代替真实手机的安全区、字体放大及触控检查；未做真机检查时明确记录未验证项。

## 8. 验收与回归

实现完成需要满足：

1. 主界面只有左上整体信息使用 Rank；Experience、七个部位及现有动作详情均为数字等级。
2. 七个入口顺序与 Home 一致；Review Progress 在 Experience 卡内；主界面不再放雷达和独立称号横条。
3. 等级映射测试覆盖 1、9、10、19、20、29、30、39、40、更高等级与全部无效输入；Cardio 不参与肌肉配色。
4. 六张 Level 插画各自验证低、中、高配色。轮廓、比例和背景不变，只有原绿色区域发生变化；Home 仍为绿色，有氧始终灰白。
5. 验证原图和去字副本哈希未变化。显示技术用独立图像对比验证非高亮区域不受影响，并检查缩小后边缘是否污染。
6. 验证三种竖屏尺寸、两种预览语言、两种计划模式；同时检查大字号可滚动兜底、44 像素触控区、键盘焦点、长名称和未评估文案。
7. 六部位详情、有氧入口、Progress 和返回路径均可用，不遗失原称号入口。没有无响应的装饰按钮。
8. 语言切换及只读浏览保持未保存输入与相关筛选；历史存储保持原结构和数值。保存训练不冒充已经更新未实现的 Rank / XP / 部位等级。
9. 从仓库根目录运行 `node mobile/scripts/build-locales.js --check` 和 `node --test`，并通过相应新增测试与浏览器检查；记录截图、检查结果和未验证项。
